# Paseo GenUI — 视觉验收

> **Visual Acceptance · v0.2**　2026-10-20
> 配套：`genui-rfc-v0.4.md`（协议与里程碑）、`genui-visual-spec.md`（尺寸与配色的唯一来源）。
> 本文件只规定"怎样才算达标、怎样验收"；具体数值一律以 `genui-visual-spec.md` 为准。内容取自上一版 `genui-visual-quality.md` 的验收部分，其 token 映射和尺寸建议已由实测规范取代。

## 1. 什么叫「达标」

本项目的视觉质量不是“具备一个边框、一个图标和一张 SVG 图”就算完成，而是满足以下五个维度：

1. **信息一眼可读**：关键数字或结论先被看到，解释其次，说明文字最后；不需要费力寻找重点。
2. **克制且精致**：大面积留白、极少装饰；颜色传达语义，不把普通文本包装成无数彩色卡片。
3. **布局自适应**：桌面宽阔舒展，手机紧凑可读；宽度变动不产生溢出、遮挡或异常空洞。
4. **局部一致**：卡片、图表、列表的字体、边框、色彩和节奏来自同一套规则；模型输出不同数据时仍保持一致。
5. **对话原生感**：GenUI 和普通 Markdown 是同一份回答的连续内容；不出现像第三方网页 iframe 一样的孤立大容器、重复标题、明显的工具调用边框。

### 1.1 视觉红线（出现一项即不通过）

- 正确数据却有截断、重叠、裁边、纵横轴错位、中文文字被挤成一字一行。
- 整张答案被做成巨大的彩色面板或套叠 3 层以上的卡片；同一个信息被三次重复突出。
- 模型输出中的 HTML/CSS、颜色值或任意尺寸被直接当成 UI 样式执行。
- 用固定的纯白/纯黑背景导致暗色模式出现刺眼亮块；为固定颜色强行牺牲文本对比度。
- 两个不同数据系列只靠颜色区分，图例与 tooltip 不一致，或坐标轴误导数值。
- 出错或流式加载时高度不断跳动，让正在阅读的聊天内容明显抖动。
- Overview 工具分组吞掉卡片，默认需要展开“调用了 N 个工具”才能看见内容。
- 仅通过单一桌面宽度的漂亮截图，就宣称“四端视觉验收完成”。

## 2. 三张参考图的视觉特征

### A · 数值对比与降幅

![参考 A：指标卡片与进度条](assets/genui/reference-a-metrics.png)

**应保留的视觉特征：**

- 标题是低强调的说明行；两张数值卡片承担主要视觉重量。
- 左右两卡的**外边距、内边距、最小高度、基线**一致；不是两个独立随意堆放的组件。
- 卡内顺序：次级标签 → 主要数字 → 弱化的附属说明；数字的字体规模明显高于标签。
- 下面的「理论月度容量减少」与 `85.7%` 是同一个指标行，之后才是细而长的进度条。
- 卡片边框细、圆角柔和、背景接近父级；不靠大阴影制造层次。
- 只有需要强调的变化才使用高饱和色，其他区域保持中性。

**反例**：两张数字卡分别用蓝色和绿色背景；数字小于标题；进度条和标签距离很远；容器套容器并叠加阴影。

### B · 分组柱状图

![参考 B：分组柱状图](assets/genui/reference-b-chart.png)

**应保留的视觉特征：**

- 图前的说明独立成一行，不重复显示一个巨大的卡片标题。
- 绘图区横向舒展，坐标刻度与淡网格线明显弱于数据柱；零基线清楚。
- 同组两系列并排，系列颜色稳定、可区分，柱宽与组间距在当前宽度下保持平衡。
- 横轴标签居中对应组，图例居中、在图下方；图例图形与柱色一致。
- 两个系列的数据大小悬殊时，低值仍可辨识，并能读取精确值。
- 整张图不被多余卡片外框与按钮栏包围。

**反例**：粗黑网格线抢视线；柱子与标签错组；文本塞到柱子里；小屏横向溢出但没有处理；图例颜色与实际系列不一致。

### C · 分级修改建议

![参考 C：分级修改建议](assets/genui/reference-c-priority.png)

**应保留的视觉特征：**

- **只用一个共享外框** 包含所有建议；内部用细分隔线自然分组。
- 左侧圆点、实心点、勾选图标承担级别区别；重点文字仍为正常正文色。
- 每组的标题与正文有清楚的间距，**长段落从正文列起始位置对齐**，不被左侧图标侵占。
- “优先修改”“其次调整”“建议保留”之间的强调度有差别，但绝不是红黄绿三张底色卡片。
- 文字自然换行，行高舒适；信息较长时容器自然增高，不裁剪。

**反例**：三个独立彩色卡；每条建议带一个醒目 badge；标题与正文在不同左边界；字间距过大；低级别建议灰到不可读。

### 2.1 对标方式

参考图按**结构、比例、层级、气质**对标；具体尺寸、字号和颜色取自 `genui-visual-spec.md` 的实测数值，而不是从截图上量像素：

| 对标项目   | 核心判断                             | 原图可提供的信息                                                |
| ---------- | ------------------------------------ | --------------------------------------------------------------- |
| 结构       | 哪些信息在同一容器、出现顺序是否正确 | **必须遵循**                                                    |
| 视觉权重   | 用户第一眼看到哪里                   | **必须遵循**                                                    |
| 间距与比例 | 留白、边框、图高是否舒服             | **需要按界面宽度归一化**                                        |
| 字体与字重 | 主次是否鲜明                         | **以 `genui-visual-spec.md` 为准**（系统字体栈）                |
| 颜色       | 是否克制、语义是否清晰               | **以 `genui-visual-spec.md` 为准**（GenUI 专用变量，亮/暗两套） |
| 绝对像素   | 该图片上的 x/y、字体尺寸、柱宽       | **不能直接当成实现值**；实现值取自 `genui-visual-spec.md`       |

## 3. 空态、错误态和流式态也属于视觉质量

### 3.1 启动与增量更新

- 工具调用刚开始时，可先显示**与最终组件外形相近**的骨架；不要先显示一个巨大的“运行工具中”卡，再突然替换成正常内容。
- 流式局部数据要按 RFC v0.4 的安全校验界限处理：**未完整校验的字段只能参与受限、无副作用、可撤销的预览**，不能被视为已成功的最终结果。
- 组件从骨架到完整内容时，应尽量保持预计高度；如果需要增高，动画要温和，尊重系统 Reduced Motion。
- 客户端应使用源 Timeline 的稳定标识；数据增量不应反复卸载重建整个组件，导致当前滚动位置漂移。
- 生成中不会因为单个文本字段尚未到达而出现一个空白的大方框。

### 3.2 失败与降级

- 校验失败的 `render_ui` 调用不会作为一张红色“错误数据卡”占据内容主体；可在普通工具详情中提供诊断。
- App 渲染失败时以**低强调、可读**的文本回退，优先 `fallbackText`；给出“查看数据”入口但不污染正文。
- 新旧客户端不支持某类组件时，信息必须可读，不以布局正确为由隐藏数据。
- “查看数据”“复制为文字”的入口位置、按钮样式及交互与 Paseo 既有通用组件一致；不自创“去网页查看”的外链按钮。

### 3.3 历史与重复渲染

- 重新打开历史、滚动出屏幕后返回、断开重连，不应因随机颜色或数组不稳定排序改变同一张卡片的视觉结果。
- 不得重现生成中的 Skeleton 作为“历史已完成消息”的首屏内容。
- 相同数据、相同主题、相同容器宽度应产生可复现的布局；生成过程的状态不是历史数据的永久一部分。

## 4. 可访问性、可读性与国际化

- 目标参照 WCAG 2.2 AA：普通文字与背景的**对比度至少 4.5:1**，大号字至少 `3:1`，必要的非文本信息（例如进度轨道与焦点）至少 `3:1`。实际颜色以平台语义色和可用性检查为准。
- 图表信息不得只靠颜色；屏幕阅读器能读取标题、轴含义、系列、类别、值与单位。
- 建议 `priorityList` 的每一项有可读的标题和级别；屏幕阅读器不应只读出“实心圆”。
- 进度条提供值、最小值、最大值及标签；图表必要时通过“查看数据”提供等价表格视图。
- 支持动态字号与粗体文本系统设置；保证 200% 缩放仍能读完全部信息。
- 不能把 `HC`、`Token`、`$`、`%` 的格式错误归咎于中文断行；需要专门的格式化规则。
- 降低动态效果设置下去掉不必要动效，仍保留加载状态反馈。

## 5. 视觉基线与测试夹具

### 5.1 标准数据必须确定且可复现

应固定三份 Fixture，避免 Agent 每次重新编造测试数据导致截图不可比：

| Fixture                 | 关键内容                                                                     | 必须验证                                          |
| ----------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------- |
| `reference-a.json`      | `old=7500`、`new=1071`、单位 `HC`、附属价值 `$375` / `≈$53.57`               | 降幅 `85.7%`；双列、单列、数值层级、进度条        |
| `reference-b.json`      | DS V4.1 Flash `7.8 / 1.1`，GLM-5.3 Flash `9.5 / 1.4`；两系列 `旧套餐/新套餐` | 标度正确、0 基线、图例一致、小柱可识别            |
| `reference-c.json`      | `change(high) / adjust(medium) / keep` 三条，包含换行和中文引号              | 单外框、分隔线、图标列、正文自然换行              |
| `pie-distribution.json` | 开发 46%、测试 27%、设计 17%、其他 10%                                       | SVG 扇区角度、标签避让、图例、tooltip、移动端窄屏 |

这些 Fixture 应是**不调用模型**就能在组件预览页和自动化测试里渲染的固定输入。`reference-a.json` 含 `compare.changeIntent: "bad"`，降幅与变化条应显示为危险色。

### 5.2 必须采集的截图矩阵

| 场景                | Web/Electron                       | iOS                  | Android              |
| ------------------- | ---------------------------------- | -------------------- | -------------------- |
| 默认浅色，正常字号  | **必须**（至少 820 和 560 内容宽） | **必须**（手机窄宽） | **必须**（手机窄宽） |
| 默认暗色            | **必须**                           | **必须**             | **必须**             |
| 125% / 150% 字号    | **必须**                           | **至少一轮**         | **至少一轮**         |
| 最窄宽度 / 超长数据 | **必须**                           | **必须**             | **必须**             |
| 历史恢复和实时生成  | **必须**                           | **必须**             | **必须**             |

额外检查：Electron 隐藏/展开侧边栏、不同窗口尺寸；iOS/Android 横竖屏；中英混排、长模型名、系统 Reduced Motion，以及 Paseo 亮/暗切换时 GenUI 变量随之切换。

自动化 Screenshot Golden 要在稳定环境（固定字体、尺寸、主题、系统缩放）生成**项目自己的**基准图；原始 ChatGPT 参考图用于人工逐项对照布局质量，**不要**把不同字体栈与设备缩放下的整图逐像素 Diff 作为唯一通过条件。

### 5.3 人工质量评分（满分 100）

| 维度             |    权重 | 给分依据                                                       |
| ---------------- | ------: | -------------------------------------------------------------- |
| 信息层级         |      20 | 重要数字/结论一眼被看到，不需要从噪声里找                      |
| 排版与比例       |      20 | 对齐、留白、宽高比例、长文本换行自然                           |
| 文字质量         |      15 | 字号、字重、行高、中文标点、单位合理                           |
| 数据与图形可读性 |      15 | A/C 的数值与级别准确，B 的轴、图例、系列、tooltip 与极端值正确 |
| 响应式质量       |      15 | 桌面/移动不溢出，不牺牲文字或交互                              |
| 主题与状态       |      10 | 明暗、加载/错误、语义色、可访问性                              |
| 一体感与细节     |       5 | 与 Paseo 正文无缝衔接，没有网页框架感                          |
| **总分**         | **100** | 参考图与实机截图共同评审                                       |

**建议发布门槛**：三个参考场景各自 `≥85/100`；其中“信息层级”“排版与比例”“数据与图形可读性”单项不能低于其满分的 80%。任何 §1.1 红线或核心数据错误都是**硬失败**，无论总分。评分应保留截图与明确的扣分说明；不能只说“看起来不错”。

## 6. A / B / C 可执行视觉验收清单

### A — Metric Comparison

- [ ] 宽屏两张 metric 子卡等宽，边线、圆角和内边距一致。
- [ ] 数值是视觉主角，标签与说明明显次一级；单位跟随数值。
- [ ] 正文阅读列和卡片左右对齐；不额外出现一层通用 Tool Call 卡片。
- [ ] 从 `7,500`、`1,071` 计算并显示 `85.7%`；显示位置与参考一致。
- [ ] 进度条填充方向、幅度及文字语义一致，长度不超过轨道。
- [ ] 手机单列、长数字、长单位、两行附属说明时仍对齐可读。
- [ ] 黑暗主题切换时卡片不是固定白底，颜色取自暗色那套 GenUI 变量。
- [ ] `changeIntent: "bad"` 时降幅数字和变化条为危险色；`"good"` 为成功色；省略或 `"neutral"` 为次要文字色。颜色不随数值正负自动变化。

### B — Grouped Bar Chart

- [ ] `7.8 / 1.1` 和 `9.5 / 1.4` 对应正确类别与系列，无错组。
- [ ] y 轴包含零，刻度自然，网格线不抢视觉，零基线正确。
- [ ] 同组柱距、组间距、轴标签居中关系合理。
- [ ] 图例排序和系列颜色全程一致，图例在图下方且不过度拥挤。
- [ ] 浅色/暗色、桌面 hover / 手机 tap 均可查询精确值和单位。
- [ ] 390px 左右的窄屏下无意外横向溢出，类别名保持完整可访问。
- [ ] 空值、零、负值、极值测试不产生假柱或非法尺寸。

### C — Priority List

- [ ] 只有一个共享外框，三项之间用浅分隔线。
- [ ] change / adjust / keep 三种行动图标区别明确，不仅靠颜色。
- [ ] 标题和正文位于同一文字对齐轴，长中文不碰撞图标。
- [ ] 正文不像一个个警告徽标，保持普通阅读文字的权重。
- [ ] 仅一项、多项、长段落、中文引号与英文混排都正确换行。
- [ ] 手机、暗色、放大字号仍是自然分组，不是“巨大彩色卡片墙”。

### D — 共用场景（所有十个组件）

- [ ] 无新增不必要的外框、阴影、装饰图标和重复标题。
- [ ] 主题切换与字号变化后不出现裁切、闪烁或不可读文本。
- [ ] 生成中骨架与完成态不产生明显跳动；历史恢复显示最终态。
- [ ] `render_ui` 默认作为可见内容，不被 Overview 工具调用分组折叠。
- [ ] 查看数据与复制文字有可用入口且不遮挡内容。
- [ ] HTML/CSS/脚本数据不会穿透视觉层成为可执行样式。

### E — Pie Chart（修订版 v1 新增）

- [ ] 四类 46/27/17/10 的真实比例正确，不将小扇区画得与大扇区同面积。
- [ ] 图例按输入顺序且标签完整，桌面/手机均可查到原始值与百分比。
- [ ] 深色主题和 390px 窄屏下图例不遮挡图形，不出现意外横向溢出。
- [ ] 全零、负数、单项占 100%、极小扇区、缺失标签被合理拒绝或显示空态。

## 7. v1 发布门槛与长期目标

### v1 的通过条件

1. A/B/C 三个固定 Fixture **逐项通过 §6**，在 §5 的跨端矩阵有真实截图证据。
2. 三项视觉评分均 `≥85/100`；没有 §1.1 的视觉红线。
3. 饼图 E 测例通过专项检查；其余 v1 组件继承同一套视觉语言，无明显脱节的样式。
4. 普通文本与 GenUI 的组合自然，用户不需要打开 HTML，也不需要手动展开工具组。
5. 数字和可视化始终一致；失败和缺失数据不会伪造一个“看起来漂亮”的错误结果。
6. A/B/C 卡片在与参考图相同宽度下截图，与参考图并排对比，由用户确认通过。

### v2 及之后

v1 先把**视觉语言和组合原语做好**，不是把 GenUI 的长期能力限制为十张固定模板。未来增加时间线、步骤、更多图表、图片、轮播、交互表单等时，均应复用本文件定义的**层级、颜色语义、密度、可访问性、测试策略**，并按新增组件特点扩展专项验收；不因新增组件数量而牺牲已建立的视觉质量。
